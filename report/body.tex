\section{引言}

本次作业要求数出照片里有多少粒米，并解决连体米粒计数不准的问题。
具体用什么方法、分哪几步，是留给我们自己想的部分。

我先按最基本的思路做了一遍，先转灰度，再用 Otsu 法\cite{otsu1979}自动选一个阈值把米粒和背景分开，再统计连通域的个数，连通域指二值图中连在一起的一片前景像素，正常情况下一粒米就是一个连通域。米粒互不接触时，这一流程没有问题；一旦两粒米挨在一起，它们在二值图中连成一块，只被计为 1 粒，米粒越密，漏计越多。
实测粘连率 80\% 时平均少数 38.9 粒，这条误差曲线见图 \ref{fig:curve}，也正是本次作业的难点所在。

我查阅文献时注意到，这个问题在已发表的工作中也常被回避。
Kurade 等人\cite{kurade2023}的米质检测系统采用“腐蚀取标记 + 注水分割”，
注水分割即 watershed 算法，常译作“分水岭算法”。
该文承认这一算法分不开互相接触的米粒，因而把这些米粒从数据集中剔除。
本文试着解决这一问题。

本文的工作可以概括为以下四点。
\begin{enumerate}
  \item 由程序从图像自身量出单粒米的尺寸与形状，后续判据均以此为单位，像素常数是不固定的；
  \item 不预先指定颜色通道与阈值方式，而是把若干组合逐一试过，按一个打分函数自动选取；
  \item 以“又大又凹”为条件，判断连通域是否为粘连块，再用注水分割切开；
  \item 切分后按面积与形状复核，并剔除硬币、边框等非米目标。
\end{enumerate}

在三组性质不同的数据上，上述方法的平均绝对误差为 4.73、1.77 与 1.93 粒，
优于本文实现的五种经典对比方法；粘连率 80\% 时误差约为直接统计连通域的十一分之一。
在此之外，本文还用 SAM 3 的输出作伪标签蒸馏了一个 27 万参数的小网络，
详见第 \ref{sec:student} 节，其总体误差进一步降到 0.68 粒。
代码、数据来源与复现方式见附录 \ref{app:repro}。

\section{相关工作}

分开粘连目标大致有两种思路。

一种是从轮廓入手。两粒米的接触处在轮廓上是一个凹点，找到凹点再连线切开。
Tan 等人\cite{tan2019}用这种方法处理粘连稻谷，
Avzalov 等人\cite{avzalov2025}进一步用椭圆拟合滤除假凹点。本文将后者实现为对比方法 B5。

另一种是从区域入手，先用注水分割\cite{vincent1991}切开，再修正结果。
Gamarra 等人\cite{gamarra2019}先以大小和凸性判断哪些区域需要切分，切开后再合并过碎的部分。
本文方法属于后一类，结构上与之相近；我实现该方法以后查文献，才发现有前辈用过类似的方法的。

\subsection{几个基本概念}

\textbf{距离变换 $D$} 是指对每个像素，算出它到最近背景像素的距离。
米粒中间的值大、边缘的值小，像一座山；两粒米粘连的地方会出现一道山谷。

\textbf{种子} 是人为指定的若干起点，一个种子代表一个要分出来的目标。
放种子相当于告诉程序“这里有一粒米”，它并不需要标出米粒的完整轮廓，
落在米粒内部的一小块像素即可。

\textbf{注水分割} 相当于把距离图看成地形图，从每个种子处开始“注水”，
水面自种子向四周漫开，两股水相遇的地方就是分界线。
给几个种子就切成几块，所以一个粘连块最后被算作几粒，完全取决于种子怎么放。

\textbf{凸实度 $\rho$} 是区域面积与其凸包面积之比，凸包即包住该区域的最小凸多边形。
一粒米接近凸形，$\rho$ 接近 1；两粒粘在一起，接缝处凹进去，$\rho$ 会变小。

\subsection{自适应二值化}

起初直接用“根据灰度二值化”的方法，但在真实照片上测试时出了问题。
白米放在深色衬布上、衬布又铺在浅色桌面上，画面有三个亮度层次，
而二值化只分两类，结果把整块衬布判成前景，一张图只数出 1 个连通域。

由此可见，通道、类数与前景极性都不宜事先指定。
本文把这三者展开成候选集合，通道取灰度或 HSV 饱和度，阈值取 2 类或 3 类 Otsu，
前景取亮或暗——逐一二值化，再用下式打分择优。
\begin{equation}
  \mathrm{score} = N\sub{单} \cdot A_0 \cdot \gamma
  \label{eq:score}
\end{equation}
式中 $N\sub{单}$ 为尺寸接近单粒的连通域个数，$A_0$ 为估计的单粒面积，
$\gamma$ 为前景与紧邻背景的灰度差。$\gamma$ 一项是后来补上的。
合成图的饱和度通道会被噪声打成上千个小斑点，只算前两项时它们反而得分最高；
这些斑点与背景几乎没有反差，计入 $\gamma$ 后便被排除。

此外还有若干合理性检查，例如米粒长宽比应在 1.25 至 8 之间、
单粒面积不超过画幅的 1\%。这些检查最初只设了下界，
结果 D3 中有 67 张图把木框条纹当成了“米粒”——其长宽比达 25，一条就占画面的 3\%。
此后，我又补上判断条件的上界、并在检查不通过时回退到下一候选，这 67 张图的平均误差由 11.45 粒降至 3.57 粒。

\subsection{米粒尺度自标定}

后续每一个判断——多大算大、多凹算凹——都需要一个参照物。
三组数据的米粒尺寸相差悬殊，短轴自 4 像素至 25 像素，固定像素数难以通用，
因此只能由程序从每张图上把米粒尺度测出来。

最初的想法是取面积分布中最小的那个峰作为单粒，实测常常选中比米粒更小的碎屑；
改取出现次数最多的尺寸，即面积分布的最高峰，才稳定下来，实现见代码 \ref{code:a0}。
面积先取对数，因为粘连块的面积大约是 $A_0$、$2A_0$、$3A_0$……，
取对数后这些峰间距相等，更容易看清，见图 \ref{fig:calib}。
得到 $A_0$ 后，再从同一批接近单粒的连通域里量出短轴 $b_0$、凸实度 $\rho_0$、宽度 $w_0$。

\begin{lstlisting}[float=!htbp, caption={估计单粒面积 $A_0$}, label={code:a0}]
def estimate_a0(areas):
    """取对数面积分布的最高峰作为单粒米面积"""
    log_s = np.log(areas)
    kde = gaussian_kde(log_s)                 # 核密度估计，相当于平滑的直方图
    grid = np.linspace(log_s.min(), log_s.max(), 512)
    a0 = np.exp(grid[np.argmax(kde(grid))])   # 最高峰对应的面积
    # 再取 0.65~1.45 倍 A0 之间的连通域求平均，结果更稳
    band = areas[(areas >= 0.65 * a0) & (areas <= 1.45 * a0)]
    return band.mean() if len(band) > 0 else a0
\end{lstlisting}

\subsection{判断是否粘连}
\label{sec:touch}

连通域比单粒米大，未必就是粘连，也可能只是一粒偏大的米。
两粒米贴合处一般会形成凹陷，因此本文要求“既大且凹”两个条件同时成立。
起初用的是“或”，本想宁可多切，实测在真实照片上误差反而增加 1.7 粒。

米粒很小时，边缘锯齿明显，凸实度已不可靠。
这时改用区域内最大内切圆的直径 $w$，它等于距离变换最大值的两倍。
两粒米并排时面积翻倍而“厚度”不变，所以改用面积与厚度的比值来判断，实现见代码 \ref{code:touch}。
一粒大米的这个值约为 1，两粒并排约为 2。

\begin{lstlisting}[float=!htbp, caption={判断一个连通域是不是粘连块}, label={code:touch}]
def is_touching(c, cal):
    """c 是一个连通域，cal 是自标定得到的单粒米参数"""
    if c.area <= 1.2 * cal.a0:            # 不比一粒米大，不算粘连
        return False
    if cal.b0 < 4.5:                      # 米粒太小，凸实度量不准，改看厚度
        e = (c.area / cal.a0) / (c.width / cal.w0) ** 2
        return e > 1.5
    return c.solidity < cal.rho0 - 0.06   # 又大又凹才算粘连
\end{lstlisting}

\subsection{放种子并切开粘连块}

判出粘连块之后，还要决定给注水分割放几个种子，也就是认定这一块里有几粒米。
最先想到的是限制种子之间的最小距离，稍作计算便知此路不通。
米粒细长，长宽比约 3.7，一粒米内部距离变换的“山脊”比两粒并排时的中心间距还长，
最小距离取多少都难以兼顾这两个要求。

换一个角度就有了出路。两粒米之间是一道深谷，一粒米内部只是浅浅的起伏，
该看的是深度而非距离。为此对距离变换取 h-maxima，
把高度不足 $h=\beta b_0/2$ 的小峰抹平，实现见代码 \ref{code:split}。
此处用短轴 $b_0$，是因为两粒米能靠多近取决于它们的宽度。

\begin{lstlisting}[float=!htbp, caption={放种子并做注水分割}, label={code:split}]
def split_cluster(mask, cal, beta=0.45):
    dist = cv2.distanceTransform(mask, cv2.DIST_L2, 5)
    h = beta * cal.b0 / 2                  # 深度门限跟着米粒宽度变
    seeds = label(h_maxima(dist, h))       # 只留下足够高的山峰作种子
    if seeds.max() <= 1:                   # 只有一个种子，不用切
        return (mask > 0).astype(int)
    return watershed(-dist, seeds, mask=mask > 0)
\end{lstlisting}

\subsection{检查与修正}
\label{sec:correct}

注水分割只回答了“可能在哪里切”，切得对不对还要再检查。一个粘连块从切开到定出粒数的全过程见图 \ref{fig:cluster}，整个计数过程见代码 \ref{code:count}。
碎块并入邻居；切完后仍然又大又凹的块，说明没切开，就按面积补数；
面积超过 $3A_0$，并且厚度满足 $w > 2.5\,w_0$ 或者和单粒一样凸的，判为异物。

\begin{lstlisting}[float=!htbp, caption={计数主循环}, label={code:count}]
total = 0
for c in components:
    if c.area < 0.3 * a0:                  # 碎屑，忽略
        continue
    if is_foreign(c, cal):                 # 硬币、木框等，不计数
        continue
    if not is_touching(c, cal):            # 单独的一粒
        total += 1
        continue
    parts = merge_small(split_cluster(c.mask, cal), a0)  # 小于 0.4*A0 的碎块并入邻居
    for p in regionprops(parts):
        k = p.area / a0
        if k < 0.4:                        # 没有邻居可并的碎块
            continue
        if k > 1.5 and p.solidity < cal.rho0 - 0.03:
            total += round(k)              # 没切开，按面积补数
        else:
            total += 1
\end{lstlisting}

异物判据的依据有两条。米粒只是相互挨着、不会融为一体，因此一堆米最厚处仍只有一粒米那么厚；
几粒米粘连通常会留下凹口，面积数倍于单粒却与单粒一样凸的区域，多半不是米堆。
实测单粒的 $w/w_0$ 介于 0.98 与 1.14 之间，真实粘连块不超过 2.0，而硬币为 8.6、木框条约为 4。
该判据最初是照着 D1 中的硬币写的，要求“更凸且更圆”；
D3 的木框条比米粒更细长，恰好从“更圆”这一条漏了过去。
去掉这一多余条件后，D3 误差由 2.34 粒降至 1.55 粒，D1、D2 则没有变化。

米粒基本不粘连。

\textbf{D2，自制合成图，40 张。} 从 RICE 数据集\cite{ds_grains}中 Karacadag 品种的单粒米照片里
抠出米粒，随机旋转、缩放后贴到深色画布上，
粘连率分 0\%、20\%、40\%、60\%、80\% 五档，每档 8 张，每张 44--98 粒。
其价值在于真值由构造方式精确给定，且粘连程度可控。

\textbf{D3，低分辨率，719 张。} 取自 Roboflow 上的 RICE 数据集\cite{ds_d3}，
$224\times224$ 的小图，每张约 14 粒。该数据集导出时做过翻转增强，同一源图存在多个副本，
按源图名去重后保留 719 张。

\subsection{评价指标}

记第 $k$ 张图的真值为 $g_k$、预测为 $p_k$，主要指标为平均绝对误差
$\mathrm{MAE}=\frac1n\sum_k|p_k-g_k|$，同时给出准确率 $1-\mathrm{MAPE}$ 与最差单张误差，
其中 MAPE 为平均相对误差 $\frac1n\sum_k|p_k-g_k|/g_k$。
平均值小并不排除个别图像错得离谱，两者需要一并看。

\subsection{与其他方法比较}

为使比较只落在“如何分开粘连”这一步上，所有方法都跑在同一份二值图上。
B1 直接统计连通域个数，即不对粘连作任何处理；B2 用前景总面积除以单粒面积；
B3 距离变换注水分割，种子取 $D > 0.5\max D$，这是 OpenCV 教程的做法；
B4 腐蚀后取连通域作种子，即文献\cite{kurade2023}的做法；
B5 轮廓凹点 + 椭圆拟合\cite{avzalov2025}。
另外还和视觉大模型 SAM 3 做了对比，详见第 \ref{sec:sam3} 节。

\subsection{图像质量变差时的表现}
\label{sec:robust}

为了解方法的失效边界，本文在 D2 上人为施加模糊、噪声、对比度压缩与降采样四类退化
结果见表 \ref{tab:robust}，其中模糊强度以单粒宽度 $b_0$ 为单位。

噪声、对比度、分辨率三项的影响都不大。噪声加到 45 个灰度级、对比度压到 8\%，
误差未见上升；降采样至 1/6 时米粒只剩约 2 像素宽，中位误差为 4 粒，属于优雅退化。

\subsection{让程序跑得更快，先找瓶颈再谈 GPU}
\label{sec:gpu}

最初 D2 每张需 6.6 s，我的第一反应是“慢就上 GPU”。
先做了一次性能剖析，也就是统计程序在各个函数上花掉的时间，结果与设想相去甚远。
逐像素运算中，Otsu 为 0.6 ms、连通域标记 2.0 ms、距离变换 3.2 ms，8 个候选全算一遍也只有约 50 ms，
不到总时间的 1\%；\textbf{98\% 花在逐个连通域算凸包和长短轴上}——Python 里的逐对象循环，
搬到 GPU 上并不会变快。原因在于一张 D2 图的 8 个候选共约 18300 个连通域，
其中真正可能是米粒的只有灰度通道的约 180 个，其余皆为饱和度通道的噪点，
而程序对它们也逐个算了凸包。

这三步能想到，和上学期的两门课有直接关系。
\textbf{操作系统原理}讲进程与线程调度时说过，线程不是越多越好，
线程数超过核数之后，时间会花在上下文切换和争抢上，反而更慢。
所以当我看到"一张图占了 17 个核却还很慢"时，第一反应就是去查线程数，
而不是去买更好的显卡；多进程并行为什么一开始没有效果，也是同一个道理——
每个进程内部又各自开了 20 个线程，互相抢核。
\textbf{计算机组成原理}讲的则是另一半，先看程序到底把时间花在哪一类操作上，
再决定优化什么；以及并行部件都有启动开销，粒度太小时并行反而不划算。
GPU 在 $224\times224$ 的小图上比 CPU 还慢，正是核函数启动开销大于计算本身的例子。
这两门课给我的共同提示，就是\textbf{先测量，再动手}。

\textbf{第一步，不算用不到的东西。} 面积和外接框用 OpenCV 的连通域统计一次取回；
长短轴改用二阶矩批量算出，与逐对象结果的差别在 $10^{-11}$ 量级；
凸包只给面积大于 $0.3A_0$ 的区域算——更小的会被当作碎屑丢掉，不会被问到凸实度。
D2 由此降到 2.7 s。

\textbf{第二步，把线程数限制为 1。} 这一步颇违直觉。我本以为程序是单线程的，
实测却发现处理一张图占满了 17 个核——标定中有大量很小的矩阵运算，
OpenBLAS 默认开 20 个线程去应付，调度开销远大于计算本身。
锁成单线程后，单张反而更快，D1 由 693 ms 降至 431 ms，D3 由 82 ms 降至 45 ms。
这也解释了多进程起初几乎没有加速的原因——各进程争抢的是同一批核。
线程锁定之后再按图并行，D3 用 20 个进程处理 240 张仅需 2.0 s，
合每张 8.4 ms，相对单进程提升 4.4 倍。

\textbf{第三步，调整判断顺序，使绝大多数凸包不必计算。} 这是收益最大的一步，
改动却只是把代码的次序换了一下。候选的得分 $N\sub{单}A_0\gamma$ 并不含凸实度，
真正用到它的只有"这批区域像不像米"那道合理性检查。
原先的写法是先检查、再排序，于是每个候选都得先把凸包算出来；
改为先按得分排序、再自高而低逐个检查后，选出的候选相同——
都是通过检查的最高分者——但排在其后的候选一次凸包也不必算。
噪点候选的对比度 $\gamma$ 很低，本就排不到前面，那 18000 多次凸包计算于是自行消失。
D2 由 2.7 s 降至 0.63 s，D1 降至 0.37 s，D3 降至 0.033 s。

以上三步在三组共 810 张图上逐张比对，计数与优化前一致，
表 \ref{tab:comparison} 中的各项指标也未发生变化。

\textbf{第四步，把逐像素的部分放到 GPU 上。} 通道转换、Otsu、开闭运算、连通域标记、
距离变换改用 CuPy 和 cuCIM；注水分割仍留在 CPU 上，因为 cuCIM 没有 GPU 版本，
而它只在很小的粘连块截图上运行，本来就不占时间。
结果见表 \ref{tab:cost}，GPU 版在 D1、D2 上分别为 0.15 s 和 0.40 s，
但在 D3 上\textbf{反而比 CPU 慢一倍}，为 0.07 s 对 0.03 s，
D3 的图只有 $224\times224$，GPU 启动核函数的开销比算完整张图还多。

精度上 GPU 版与 CPU 版接近，但并不逐张一致，差异来自两处实现细节。
OpenCV 的距离变换是近似算法，GPU 版用的是精确欧氏距离变换；
饱和度通道在 GPU 上按同样公式重算，取整与 OpenCV 略有出入。正文结果仍以 CPU 版为准。

回头看，收益最大的三步——少算用不到的区域、把线程锁成 1、调整判断顺序——
都不需要显卡，所得计数也与原来一致；
最先想到的 GPU 反倒是收益最小、代价最大的一步。整条流水线合计快约 10 倍
D2 由 6.6 s 降至 0.63 s。先测量、再优化，这是我这次最实在的收获，
也是上述两门课留下的最有用的一条经验。

\section{方法二 把 SAM 3 会的东西教给小网络}
\label{sec:student}

\subsection{为什么会有第二种方法}

第二种方法是做完上一节的实验之后才想到的。那里留下一个我不太满意的结果。
本文方法在 D3 上无论怎么调都与 SAM 3 差距明显，且失败的样子大多属于同一类——
木框亮边被当成米，颜色偏暗的米被漏掉。追究下去，
几何判据只知道米长什么样，并不知道什么是米，这一点在第 \ref{sec:limit} 节还会谈到。
既然 SAM 3 知道，能否把它知道的东西教给一个小模型？本节所做的就是这件事。

\subsection{怎么教，学生学什么}

\textbf{标签怎么来。} 用 SAM 3 处理每张照片，取其每个掩膜的质心，
得到一串点坐标作为伪标签；合成图 D2 则直接采用生成时记录的米粒中心，不必经过教师。
人工标注全程不参与训练，只用于测试。

\textbf{学生学什么。} 学的不是分割，而是密度图，即在每个米粒处放一个高斯，
整张图的积分即为粒数。这样安排有两点考虑。其一，米粒只有 4 像素宽，
要求网络给出清晰的实例边界并不现实，让它在米粒处“鼓起一个包”却是可行的；
其二，损失函数不依赖于把相邻两粒分开，而那恰是几何方法最吃力之处。
高斯的宽度按每张图自身的米粒间距确定，因此 4 像素与 25 像素的米粒在网络看来尺度相当。

\textbf{网络与训练。} 三层 U-Net，27 万参数，权重文件 1 MB。
按 7:1:2 划分训练、验证与测试集，划分以源图为单位，
以免同一张照片的增强副本跨集泄漏。在 RTX 4080 上训练 6000 步，约 6 分钟。

\subsection{走过的弯路，以及必须说清的前提}

第一次训练出来的学生总体误差为 3.31 粒，反而不如几何方法。排查出两个原因。
一是训练步数不足，训练集上的误差与测试集相当，属于欠拟合；
二是采样不均衡——训练集 567 张中 D3 占了 503 张，
按图随机取样时约有 89\% 的时间花在 D3 上，米粒最大的两组几乎没被学到。
改为先随机选数据集、再从中取图之后，D1 由 8.21 粒降至 3.91 粒，D2 由 9.03 粒降至 1.29 粒。

还有一个前提必须说清楚。学生的成绩建立在教师标签的质量之上，而这一点是实测过的。
与人工标注相比，教师给出的点在 D3 上准确率 0.993、召回率 1.000、计数误差 0.10 粒，
在 D1 上依次为 0.957、0.967 与 3.29 粒；在这两组数据上，SAM 3 的伪标签确实足够好。
但选出这套提示词本身用到了带标注的数据，因此严格地说，
学生模型省掉的是推理时的大模型，而不是标注本身。

\section{讨论}

\subsection{试过但没用的办法}

\textbf{上采样。} 真实照片中的米粒只有 4 至 6 像素宽，我曾设想先把粘连块放大再算距离变换。
实测未见改善——插值并不会凭空增加原图中不存在的信息。相关代码已删除。

\textbf{中值滤波。} 为压住饱和度通道的噪点，我曾加入 $3\times3$ 中值滤波，当时确有效果。
但式 \eqref{eq:score} 补上 $\gamma$ 之后，噪点已能被排除，两者功能重复，
而中值滤波还会把本就只有几像素宽的米粒磨掉一圈。去掉它后 D1 误差由 7.27 粒降至 4.73 粒。
由此得到的经验，是加入新机制之后应当回头检查旧的补丁是否已成多余。

\textbf{按 D3 调碎屑门限。} 调高碎屑门限能让 D3 明显变好，D1 却随之变差。
查下去才发现，D1 中那些“又小又圆”的区域其实是真米粒——
4 像素尺度下被阈值削去一截的米粒本就长这样。这等于针对单个数据集调参，故未采用。

\subsection{不足}
\label{sec:limit}

\textbf{会被“更像米粒的东西”骗过。} 我还找过另一组真实照片\cite{ds_ruler}想补充粘连数据，
结果方法在很多图上选错了前景，选中的是画面边上直尺的刻度，而不是米粒，见图 \ref{fig:scope}。
刻度大小一致、细长、对比强烈，比颜色浅淡、大小不一的米粒更符合式 \eqref{eq:score} 的要求。
这说明该准则度量的是“像不像一片重复的小目标”，而不是“是不是米”。
它只有关于形态的先验，不含关于米的语义，因此形态上更规整的重复结构就可能胜出。
此外，这组照片中相当一部分是多个稻米品种同框对照，粒径相差很大，
也不满足“同一张图内米粒尺寸相近”这一前提，故最终未用作测试集。

\begin{cfigure}
  \includegraphics[width=\textwidth]{scope_failure.png}
  \caption{方法被直尺刻度误导的两个例子，每例左为原图、右为选出的前景。}
  \label{fig:scope}
\end{cfigure}

\textbf{模糊时可能选错二值化。} 第 \ref{sec:robust} 节中崩溃的那几张图，
是因为模糊后的饱和度通道被阈值化成大量碎点，碎点数目极多，
使得式 \eqref{eq:score} 的得分反而略高于正确的候选。此问题尚未解决。

\textbf{D3 存在每图约 1 粒的假阳性。} 其来源主要是木框边缘的亮块，而非过度切分。

\textbf{合成数据会美化结果。} D2 背景干净、米粒尺寸一致、光照均匀，
连“总面积除以单粒面积”这样简单的办法都能做到 2.30 粒，
而同一办法在真实照片上的误差是 22.76 粒。看合成数据的结论时须记得这一层。

\section{结论}

本文实现了一种基于注水分割的粘连米粒计数方法。它先由图像自身量出单粒米的尺度，
据此判断粘连、控制种子数量，最后按面积与形状复核切分结果。
三组数据上的平均绝对误差分别为 4.73、1.77 与 1.93 粒，优于五种对比方法；
粘连率 80\% 时误差约为直接统计连通域的十一分之一。

做完这份作业，体会最深的一点是常见做法里有许多写死的数字，
例如阈值取 $0.5\max D$、结构元取 $3\times3$、凹点圆盘取固定半径，
它们换一张图就可能失效。B3 被一枚硬币拖垮、B5 在 4 像素米粒上整体失效，都是这个原因。
把这些数字换成从图像自身量出的量，方法才真正稳得住。

就精度而言，本文方法不及提示词选得恰当的 SAM 3；
但它不需要标注和显卡，内存仅需 0.31 GB，在没有显卡的机器上比 SAM 3 快得多，见表 \ref{tab:cost}，
且每一步的判断依据都说得清楚，出错时能查到原因。
在此基础上，本文又用 SAM 3 的输出蒸馏了一个 27 万参数的学生模型，详见第 \ref{sec:student} 节，
其总体误差低于几何方法，且无须挑选提示词——
这说明“不知道什么是米”这一缺陷，可以通过把大模型的语义知识搬进小网络来弥补。

回到题目本身。“数出有多少粒米”与“解决连体米粒计数不准”这两问，
前者在三组数据上的准确率为 95.02\%、97.46\% 与 85.96\%，
后者由图 \ref{fig:curve} 作答——粘连率升到 80\% 时，
直接统计连通域的误差为 38.88 粒，本文方法为 3.50 粒。
